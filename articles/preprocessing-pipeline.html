Building a Reliable Preprocessing Pipeline

A practical guide to missing values, categorical encoding, feature scaling, and preventing data leakage before training a machine learning model.

By Yash • Learning notes • Beginner-friendly

In this article

  • Handling missing values
  • Encoding categorical features
  • Feature scaling
  • Combining steps into a pipeline
  • Avoiding data leakage
  • Key takeaways

Training a machine learning model involves more than choosing an algorithm and calling fit(). Real-world datasets often contain missing values, categorical features, inconsistent scales, and other issues that can affect model performance.

Preprocessing is the process of preparing data so a model can use it appropriately. A well-designed workflow makes the process more consistent, reproducible, and easier to maintain.

1. Why preprocessing matters

Consider a dataset containing age, salary, city, and exam score. Some ages may be missing, city is categorical, and salary may have values much larger than age. These features need different kinds of treatment.

Preprocessing helps address such issues before the model is trained. However, the correct transformation depends on the dataset, the model, and the meaning of each feature.

2. Handling missing values

Missing values can prevent certain algorithms from working correctly or cause useful observations to be discarded. Two common approaches are removing incomplete rows and imputing missing values.

Mean versus median imputation

  • Mean: the arithmetic average. It can work well for numerical data without strong outliers.
  • Median: the middle value after sorting. It is less affected by extreme observations.

For example, if most ages in a dataset are between 18 and 30 but one value is 100, the mean may be pulled upward. The median may be a more representative choice, depending on the data.

3. Encoding categorical features

Many machine learning algorithms expect numerical input. Categorical values such as city names therefore need to be represented numerically.

One-hot encoding

One-hot encoding creates a separate binary feature for each category. For example, a city column containing Delhi, Mumbai, and Chennai can be represented by three indicator columns.

Ordinal encoding

Ordinal encoding assigns numbers to categories with a meaningful order, such as Low, Medium, and High. The order must be defined deliberately; arbitrary numeric assignments can misrepresent nominal categories.

4. Feature scaling

Features can have very different numerical ranges. For example, age may range from 18 to 60, while salary may range from thousands to hundreds of thousands.

Standardization transforms a numerical feature using its mean and standard deviation. Scaling can be important for models such as logistic regression and distance-based algorithms, though it is not equally necessary for every model. 

from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()

X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)

Important: fit the scaler on the training data only. Use the fitted scaler to transform validation, test, and future data.

5. Combining steps into a pipeline

A pipeline chains preprocessing steps and a model into a single workflow. This reduces repetitive code and helps ensure that the same transformations are applied consistently. 

from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler()),
    ("model", LogisticRegression())
])

pipeline.fit(X_train, y_train)

predictions = pipeline.predict(X_test)

This example illustrates a numerical-feature workflow. If the dataset includes categorical columns, those columns should receive appropriate encoding, often through a ColumnTransformer combined with a pipeline.

6. Avoiding data leakage

Data leakage occurs when information that would not legitimately be available during training influences the model or evaluation. It can produce misleadingly strong test results.

A common example is calculating imputation values or scaling statistics using the entire dataset before splitting it. The test set then influences the transformations used for training.

A safer workflow is to split the data first, fit preprocessing steps on the training data, and use those fitted transformations on the test data. Pipelines make this approach easier to preserve, especially during cross-validation.

Key takeaways

  • Inspect the dataset before choosing preprocessing steps.
  • Choose imputation methods based on the data and its distribution.
  • Use one-hot encoding for nominal categories and ordinal encoding when a meaningful order exists.
  • Scale features when the chosen algorithm benefits from it.
  • Fit preprocessing transformations on training data only.
  • Use pipelines to make workflows consistent and reproducible.
