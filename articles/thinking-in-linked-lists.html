Thinking in Linked Lists

Learning to think in nodes and references: how linked lists work, how to manipulate them, and how to implement them in Java.

1. Introduction

Arrays are useful when we need fast access to elements by index. But another data structure approaches storage differently: the linked list.

A linked list is a sequence of nodes. Each node stores a value and a reference to another node. Instead of relying on adjacent positions in an array, the list connects its elements through references.

The important skill is not memorizing linked-list code. It is learning to track which node points to which other node as the structure changes.

2. The mental model: nodes and connections

Imagine three boxes connected by arrows. Each box contains a value, and each arrow indicates which node comes next. 

head
 |
 v
[10 | next] -> [20 | next] -> [30 | null]

Here, head refers to the first node. That node connects to the second, which connects to the third. The final node points to null, meaning there is no next node.

The values 10, 20, and 30 are examples. The key idea is the chain of references, not the particular values.

Linked lists versus arrays

  • Array: elements are accessed by index, such as arr[2].
  • Linked list: you usually begin at the head and follow references until you reach the desired node.
  • Array: inserting into the middle may require shifting elements.
  • Linked list: inserting after a known node can require changing only a few references.

Linked lists do not automatically make every operation faster. Finding a particular position still takes time because nodes must be visited in sequence.

3. Anatomy of a node

A basic singly linked-list node contains two things:

  • Data: the value stored in the node.
  • Next: a reference to the next node, or null if there is no next node.

The head variable holds a reference to the first node. If the list is empty, head is null.

A node does not need to know the entire list. It only needs its own data and the reference specified by its structure.

Important distinction

A reference is not the same thing as a copy of the next node's data. It lets your program reach that node. Changing a reference changes the connections through which the list can be traversed.

4. Implementing a linked list in Java

Let's start with a minimal node class. This is our own implementation for learning; Java's built-in LinkedList is a separate library class. 

class Node {
    int data;
    Node next;

    Node(int data) {
        this.data = data;
        this.next = null;
    }
}

What each part means:

  • int data stores an integer value.
  • Node next can refer to another Node object.
  • Node(int data) is the constructor that runs when we create a node.
  • this.data = data assigns the constructor's argument to the object's field.
  • this.next = null initially leaves the node without a successor.

Creating and connecting nodes

Node first = new Node(10);
Node second = new Node(20);
Node third = new Node(30);

first.next = second;
second.next = third;

Node head = first;

We have created three separate objects and connected them. The head variable now refers to the first node.

Notice that creating the nodes did not automatically connect them. We explicitly established the references using next.

5. Traversal: visiting every node

Traversal means starting at the head and moving through the list one node at a time until there are no more nodes. 

Node current = head;

while (current != null) {
    System.out.println(current.data);
    current = current.next;
}

For our example, the output is:

10
20
30

The critical line is current = current.next;. It advances the reference to the next node.

If you forget to advance current, the loop repeatedly processes the same node. If you dereference current after it becomes null, Java throws a NullPointerException.

Traversal takes O(n) time for n nodes because each node is visited at most once.

6. Insertion: connecting a new node

Suppose the list is: 

10 -> 20 -> 30 -> null

We want to insert 15 after the node containing 10. Let current refer to that node. 

Node newNode = new Node(15);

newNode.next = current.next;
current.next = newNode;

The order matters. First, the new node points to the node that used to follow current. Then current points to the new node.

The resulting list is:

10 -> 15 -> 20 -> 30 -> null

If you set current.next = newNode first, without preserving the original successor, you can lose the connection to the rest of the list.

What if we insert at the beginning?

Node newNode = new Node(5);
newNode.next = head;
head = newNode;

The new node points to the old head, and then head is updated to the new node. This also works when the list was empty.

7. Deletion: bypassing a node

Suppose we want to remove the node containing 20: 

10 -> 20 -> 30 -> null

If current refers to the node containing 10, we can bypass the next node: 

current.next = current.next.next;

The resulting chain is:

10 -> 30 -> null

The node containing 20 is no longer reachable through this list. Java's garbage collector can eventually reclaim an object when it is no longer reachable and otherwise eligible for collection.

This one-line operation assumes that current and current.next are non-null. Production code must handle those cases safely.

Deleting the head

if (head != null) {
    head = head.next;
}

Removing the first node is different because there is no previous node to update. Instead, we move the head reference forward.

8. Time complexity

For a singly linked list with n nodes, the usual complexities are:

  • Access by index: O(n) in the general case.
  • Search by value: O(n).
  • Insert at the head: O(1).
  • Delete the head: O(1).
  • Insert after a node you already have: O(1).
  • Find a position and then insert there: O(n) overall in the general case.

These distinctions matter in interviews. An operation may take constant time once the correct node is known, while finding that node may still require a traversal.

9. Common mistakes

  • Losing the head: changing the head reference carelessly can make the rest of the list inaccessible.
  • Breaking the chain: overwriting a reference before preserving the original successor.
  • Ignoring an empty list: accessing head.data when head is null.
  • Incorrect loop conditions: dereferencing a null reference or stopping before processing the last node.
  • Confusing a node with its value: current refers to a node, while current.data accesses its stored value.
  • Updating references in the wrong order: especially during insertion and reversal.

10. Practice checklist

Before moving to more complex linked-list problems, make sure you can explain and implement these operations without copying the examples.

  • Define a Node class and create a few connected nodes.
  • Traverse a list and print every value.
  • Count the number of nodes.
  • Search for a given value.
  • Insert a node at the head.
  • Insert a node after a known node.
  • Delete the head safely.
  • Explain what happens when the list is empty.
  • Draw the references before and after each operation.

For each problem, first describe the reference changes in plain language. Then write the Java code. This builds the mental model needed for reversing lists, finding the middle, detecting cycles, and solving other interview problems.
